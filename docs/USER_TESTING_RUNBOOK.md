# 真实用户测试现场执行清单

本清单用于完成比赛所需的真实用户测试。系统已提供 `/teacher/user-testing` 的匿名记录与汇总功能；本文件不包含、也不能替代真实测试结果。

## 最小样本与角色

- 至少 2 位完成会话的真实参与者，建议 3 位；
- 至少 1 位人工智能/计算机相关教师；
- 至少 1 位人工智能或计算机相关学生；
- 参与者使用别名，例如 `教师测试者01`、`学生测试者01`。不要记录姓名、电话、学号、微信号或截图中的个人信息。

## 每位参与者的执行流程（约 15–20 分钟）

1. 说明用途：测试 SkillTwin AI 的可用性与结果可理解性；可随时退出，且可要求删除记录。
2. 打开教师端 `/teacher/user-testing`，点击“新建匿名会话”。
3. 填写别名、角色，选择对应脚本：
   - 教师：`教师端：产业需求到实训设计闭环`；
   - 学生：`学生端：诊断到自适应学习闭环`。
4. 只有取得本人知情同意后，勾选确认框并创建会话。
5. 让参与者独立完成脚本中的 3 个任务；观察者仅在卡住时记录现象，不替对方完成。
6. 对每项任务填写：实际结果、完成情况、预期达成度（1–5）、易用性（1–5）和可选反馈。
7. 三项均完成后，填写整体反馈，点击“结束并纳入报告”。未完整填写的会话不会进入汇总。

## 记录口径

- `actual_result` 记录可观察事实，例如“在课程 Gap 页面找到课程原文依据，但未理解 is_partial 提示”。
- 不要把观察者的推断写成事实，例如“学生能力较弱”。
- 达成度评估“是否达到脚本预期结果”；易用性评估完成该任务是否顺畅，两者不可混用。
- 若参与者中止，保持草稿或使用删除按钮删除会话及全部关联记录。

## 完成后检查

在“汇总明细”确认：

1. 已完成会话不少于 2，且角色构成与实际一致；
2. 每条汇总仅来自已完成的真实会话；
3. 若页面出现“样本少于 2 名”警告，不在 PPT 或报告中作结论性表述；
4. 根据低分任务和文字反馈形成改进项，保留“反馈 → 修改 → 复测”的记录。

比赛材料可如实表述：**“已邀请 N 名真实参与者，采用匿名任务脚本记录完成率、预期达成度、易用性与反馈；统计仅汇总已完成会话。”** 其中 `N` 必须以页面实际已完成会话数为准。
