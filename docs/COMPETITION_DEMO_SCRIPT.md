# SkillTwin AI 比赛演示脚本（6–7 分钟）

## 演示目标

在一个连续故事里展示闭环：`产业岗位需求 → 岗位能力 → 课程与实训 → 学生画像 → 自适应学习`。每一处行业结论都回到系统中的可追溯输入；没有依据时明确标注限制。

## 演示前检查（不可跳过）

1. 打开首页、教师端和学生端各一个标签页；后端健康检查应显示 database、embedding、vector store 正常。
2. 首选已预热的数据卷和 `DEMO_MODE=replay`；只回放此前真实生成并已留存的结果，绝不把生成的假内容伪装成真实模型结果。
3. 检查岗位市场页的统计样本为 **30 条 REAL 核心国内 JD**；页面应同时显示 2 条旧 DEMO 已排除，不能把它们混入统计。
4. 使用现有的公开培养方案时，保留“局部样例”的提示：当前默认方案为北京信息职业技术学院 2025 级人工智能技术应用专业（三年制）的 4 门课程、9 条技能映射，不能宣称代表本校完整培养方案。
5. 若现场网络或模型不可用，只演示可回放链路和确定性计算，不临时编造结论。

## 主线与操作

### 0:00–0:35｜开场：问题不是“少一个聊天机器人”

**操作**：首页 → 教师端入口。

**讲述**：

“职业教育最难的是把企业岗位变化，转成可教、可练、可评、可持续调整的能力。SkillTwin AI 把岗位、课程、实训和学生能力放到同一个 `skill_code` 数据主键下，形成可计算的闭环。”

### 0:35–1:30｜真实岗位需求：先给数据，再给结论

**操作**：教师端 → 岗位趋势分析，选择“AI 数据标注工程师”。打开任一技能的证据抽屉/来源。

**讲述**：

“这里的分析队列是 30 条经过来源登记的公开 REAL JD；系统存储中保留的 2 条 DEMO 只用于开发管线，已自动排除。当前技能命中覆盖为 29/30，约 96.7%；唯一未匹配岗位不会被系统强行归类。这说明我们把未知暴露出来，而不是让模型猜。”

“例如，通用数据标注在样本中出现 28/30。点击后可以回看每条岗位的公开来源和原始职责/要求摘录，所以这个排名不是大模型生成的印象分。”

### 1:30–2:25｜岗位能力图谱：把 JD 变成可审的教学对象

**操作**：教师端 → 岗位能力图谱，选择已审核版本；点击“数据标注能力”下的技能节点，展开来源、课程和掌握要求。

**讲述**：

“图谱不是一段 Markdown，而是持久化的结构化节点和边。模型只可创建草稿；教师审核后才成为下游任务、评估和路径的依据。点击节点可以看到知识点、技能点、课程关联、实训关联及来源。”

“这也让老师能把 AI 的产出改成自己的专业判断，并留下审核记录。”

### 2:25–3:15｜课程 Gap：把“需求高”翻译成可执行改进

**操作**：教师端 → 课程 Gap / 培养方案优化；展开“通用数据标注”的课程证据与建议。

**讲述**：

“系统把已审核图谱、岗位快照和课程映射以相同技能码进行比较。现有北京高职公开样例中，《数据分类与标注技术》明确覆盖数据分类、人工/半自动标注和标注质量检验，因此它不是简单建议‘新开一门课’，而是建议强化实践与评价。”

“对映射缺失的技能，系统只说‘当前局部方案中尚未映射’，不会断言本校没有教。导入本校完整培养方案后，同一算法即可重算。”

### 3:15–4:05｜从真实工作任务到学习型实训

**操作**：从图谱节点进入实训任务生成，选择“目标检测/数据标注”能力，展示任务的目标、步骤、评分 Rubric、来源与 AI 生成标记。

**讲述**：

“我们把真实岗位场景转为结构化学习任务，而不是给学生一段聊天文本。任务包含工作情境、提交物、评分量规、常见错误、安全规范和知识依据；教师可审核、发布，再由学生完成。”

### 4:05–5:15｜学生诊断：能力差距不是模型随口估计

**操作**：学生端 → 选择目标岗位 → 完成/打开诊断结果 → 能力雷达、Gap 柱状图、学习路径时间线。

**讲述**：

“学生先选定同一个岗位图谱，再完成诊断。系统用答题证据更新 Student Skill Profile，与图谱中的 Target Skill Vector 逐项相减，得到可解释的 Skill Gap。”

“因此推荐路径会优先安排差距大且有前置关系的能力，例如先补标注规范与工具，再进入目标检测实训。排序和差距由确定性计算完成，模型只负责解释和生成教学材料。”

### 5:15–6:10｜闭环：完成任务后路径重新计算

**操作**：打开一个已发布任务的提交/评估页，展示完成后画像、进度与后续推荐变化；如没有真实学生记录，使用标记为 DEMO 的受控演示账号并明确说明。

**讲述**：

“任务评估会回写能力档案，系统重新计算差距并调整下一阶段路径。这里才是 SkillTwin 的关键：不是推荐一次课程，而是在每次实训后更新学习决策。”

### 6:10–6:45｜可信与落地边界

**操作**：打开来源/审计信息或健康状态页。

**讲述**：

“系统明确区分 REAL、DEMO、AI 生成、教师审核和知识库暂无依据。当前已完成真实 JD 数据链和部署静态验证；需要与学校共同完成的是导入完整校本方案、教师审核技能表、以及至少 2–3 位真实用户的测试记录。我们不把尚未发生的验证包装成成果。”

## Q&A 备用回答

| 可能提问 | 建议回答 |
|---|---|
| 岗位趋势是否由模型生成？ | 不会。频次、占比、排名和 Gap 都是确定性计算；模型只做结构化生成和自然语言解释。 |
| 证据从哪里来？ | 每条 JD 保留来源 URL 与职责/要求摘录；知识库文档保留来源、页码/章节（存在时）和 chunk ID。 |
| 为什么只用 30 条 JD？ | 这是第一批经登记与清洗的核心国内样本，目的先验证完整数据闭环；来源登记可继续扩充，统计页面显示样本量与限制。 |
| 为什么不是所有能力都有课程 Gap 结论？ | 当前是公开的局部培养方案样例。缺映射只代表当前输入未覆盖，不代表学校没有教学；需导入完整校本方案。 |
| 断网能否演示？ | 已录制的真实模型结果可在 replay 模式回放；计算、图谱、RAG 索引和来源追溯仍在本地数据卷中。 |
